# QuantForge 系统需求文档

AI 驱动的 A 股量化分析平台：每日自动采集行情、量化生成 Top 5 推荐、跟踪 1/3/5/7 交易日收益，用历史结果验证策略可信度。

## 1. 用户角色与权限

| 角色 | 权限 |
|---|---|
| 普通用户 | 查看今日推荐、收益跟踪、涨停板、市场报告、个股分析、策略分析 |
| 管理员 | 普通用户全部权限 + 运维控制台、数据采集管理、用户角色管理、定时任务配置 |

- 认证：JWT（HS256，7 天有效期），游客可免注册登录
- 默认管理员账号 `admin/admin123`（启动时自动创建）
- 注册限制：用户名 2-50 字符、密码 ≥6 位、`guest` 为保留账号
- 接口限流：30 次/分钟/IP

## 2. 功能需求

### 2.1 推荐工作台

用户打开首页即看到今日推荐与策略表现：

1. **每日推荐**：按交易日展示 Top 5 股票，含排名、代码、名称、推荐价、综合评分、入选理由、因子评分明细
2. **策略可信度**：AI 复盘结论（含正/中性/谨慎评级与建议）、3/5/7 日均收益、平均最大回撤
3. **收益跟踪**：按推荐日期查看历史推荐的 1/3/5/7 日价格与收益率、当前价、跟踪状态（跟踪中/已完成）
4. 支持按交易日切换查看历史推荐

### 2.2 推荐生成

输入：目标交易日；输出：当日 Top 5 推荐。

流程与规则：

1. 当日已存在推荐则跳过（幂等）
2. 从当日归一化行情快照构建候选池（Top 50），快照缺失则报错，不得静默生成
3. 策略评分（版本 `qf-db-strength-v2`）后取前 5 名入库
4. 评分因子与权重：

| 因子 | 权重 | 计算 |
|---|---|---|
| 动量 momentum | 30% | `clamp(50 + 涨幅×6)` |
| 趋势 trend | 25% | `clamp(连涨天数×18)` |
| 流动性 liquidity | 20% | `clamp(换手率×8)` |
| 数据源质量 source_quality | 15% | db_snapshot=92 / lxsz、akshare、tencent=88 / 其他=70 |
| 风险惩罚 risk_penalty | -10% | 涨幅≥8% +35；换手≥18% +20；连涨≥5 天 +15 |

5. 硬性过滤：价格 <5 或 >80 元、创业板/科创板/北交所、当日跌幅 >-3%，均剔除
6. 排序：评分降序 → 连涨天数降序 → 换手率降序 → 代码升序

### 2.3 收益跟踪

1. 里程碑：推荐后第 1/2/3/5/7 个交易日
2. 基准价 = 推荐价；收盘价取日线表，缺失时回退快照表
3. 填满第 7 日即锁定为 `completed` 并记录最终收益率
4. 记录最大区间收益与最大回撤
5. 仅跟踪 `tracking` 或第 7 日收益缺失的记录；已完成记录不可重复计算
6. 管理操作：单条/批量重置、删除、整日编辑（改推荐价/理由/删条）

### 2.4 涨停板分析

1. 展示指定交易日涨停池：按连板数分组（首板/2板/3板/4板+）
2. 字段：代码、名称、涨幅、最新价、成交额、市值、换手率、封单额、封板时间、开板次数、连板数、封板强度、行业
3. 行业热度聚合（数量、龙头、最高连板、平均封板强度）
4. 汇总：涨停总数、最高连板、首板数、炸板率、平均封板强度、总封单额、最强行业
5. 数据来自已落库采集结果，页面不直接请求外部接口；支持近 60 天日期切换

### 2.5 市场报告

1. 每日收盘后生成 AI 市场报告：三大指数、热门板块、北向资金、涨停板分析、AI 复盘
2. 数据全部来自已落库采集结果；板块/北向/涨停缺失时降级跳过，指数缺失则生成失败
3. 涨停板分析维度：行业分布、连板股、一字板、封单强度 Top10、最高连板、昨日涨停今日表现
4. 输出：JSON 数据入库存档 + 可选自包含 HTML 报告（K 线/MACD/KDJ/板块排行/涨跌家数/指数对比图表）
5. 支持按日期查看历史报告

### 2.6 个股分析

输入股票代码，输出：

1. AI 多维度分析报告（基本面/技术面/消息面）
2. 基本信息、日线行情（可指定天数与复权方式）、指数行情、热门板块

### 2.7 策略分析

基于历史推荐记录的纯数据库统计分析（不调用外部接口）：

1. 胜率趋势、收益分布、持有期比较（3/5/7 日哪个更优）、最佳持有期
2. 按星期/价格区间/股票类型/波动率的收益表现
3. 风险指标：平均最大回撤
4. AI 洞察作为辅助解释

### 2.8 运维控制台（管理员）

1. **单日闭环**：一键执行 采集 → 归一化 → 生成报告 → 生成推荐 → 更新收益
2. **区间回测**：起止日期内逐交易日独立采集与生成，完成后统一更新收益
3. **单独操作**：只采集、只生成推荐、只更新收益
4. **异步任务**：生成任务后台执行，可查询进度（步骤/百分比）与结果
5. **定时任务配置**：
   - 开关、运行时间、是否生成报告/推荐/更新收益
   - 仅工作日执行，非交易日自动跳过
   - 采集全部成功后才会执行报告/推荐/收益工作流
   - 每次执行记录结果日志
6. **数据采集管理**：
   - 查看 6 类数据源采集状态、质量检查结果、采集日志
   - 单项/全量补拉、归一化重跑、删除指定日期数据

### 2.9 数据采集

1. 采集 6 类数据：指数日线、板块汇总、交易日历、北向资金、涨停池、全市场快照
2. 多源互备：AKShare → 腾讯 → 新浪按优先级自动降级，全部失败时报错
3. 幂等：同日同类型已采集则跳过
4. 失败重试：最多 3 次指数退避（1s/3s/9s）
5. 原始响应全文落库 + 采集日志（状态/耗时/大小/错误/重试次数）
6. 归一化为快照表/日线表/候选池，并写入质量检查记录

## 3. 数据需求

### 3.1 数据表

| 表 | 用途 |
|---|---|
| users | 用户（角色：admin/user/guest） |
| recommendations | 推荐记录与收益跟踪 |
| market_reports | 市场报告 |
| raw_data_records | 采集原始数据（唯一 data_type+target_date） |
| data_fetch_log | 采集日志 |
| stock_spot_snapshots | 全市场快照（唯一 trade_date+stock_code） |
| stock_daily_bars | 日线（唯一 trade_date+code+adjust） |
| stock_candidates | 候选池（唯一 trade_date+stock_code） |
| data_quality_checks | 数据质量检查（唯一 trade_date+data_type） |
| generation_tasks | 后台生成任务 |
| schedule_configs | 定时任务配置（单行） |

### 3.2 推荐记录字段

rank、stock_code、stock_name、recommend_price、score、strategy_version、factor_snapshot、reason、status（tracking/completed）、tracking_days、price_day{1,2,3,5,7}、return_rate_day{1,2,3,5,7}、current_price、return_rate、final_return_rate、max_gain、max_drawdown

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 幂等 | 采集、报告生成、推荐生成重复执行不产生重复数据 |
| 缓存 | 推荐/统计/仪表盘查询缓存，数据变更后即时失效 |
| 异步 | 耗时的报告/推荐生成走后台任务，前端轮询进度 |
| 部署 | 一键部署脚本；后端 8084、前端 3002 |
| 配置 | 数据库、LLM、JWT 密钥均环境变量化 |
| 数据源隔离 | 页面与策略生成不得直接请求外部行情接口 |
