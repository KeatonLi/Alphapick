# 数据分析功能设计文档

## 背景

QuantForge 已积累大量历史推荐数据（recommendations 表），但目前只展示收益跟踪，没有深入分析这些数据背后的规律。用户希望挖掘历史数据价值，发现市场规律，优化推荐策略。

## 目标

1. **时间维度规律挖掘**：分析周几推荐效果最好、月份规律、节假日效应
2. **持仓周期优化**：确定最优持仓天数，验证当前3天跟踪期是否最优
3. **自动生成洞察**：用文字说明关键发现，给出可操作的建议
4. **日线级别分析**：只分析日线数据，不做实时分析

## 非目标

- 不做实时行情分析
- 不做个股技术分析（已有功能）
- 不做 AI 策略建议（留给方案三）
- 不做情绪关联分析（数据量不足）

### 数据流

1. 用户访问 `/analysis` 页面
2. 前端调用 `/api/analysis/*` 接口
3. 后端 `analysis_service` 查询 `recommendations` 表
4. 统计计算后返回结构化数据
5. 前端渲染图表和洞察卡片

## 数据模型

### 使用的现有字段

```sql
-- recommendations 表
recommend_date      DATE           -- 推荐日期（分析时间维度）
stock_code          VARCHAR(10)    -- 股票代码
return_rate_day1    DECIMAL(10,4)  -- 第1天收益率
return_rate_day2    DECIMAL(10,4)  -- 第2天收益率
return_rate_day3    DECIMAL(10,4)  -- 第3天收益率
final_return_rate   DECIMAL(10,4)  -- 最终收益率
tracking_days       INT            -- 跟踪天数
recommend_price     DECIMAL(10,3)  -- 推荐价格
current_price       DECIMAL(10,3)  -- 当前价格
```

### 新增计算字段（内存计算，不存库）

```python
# 胜率计算
is_win = final_return_rate > 0

# 持仓天数分组
holding_days = 1, 2, 3  # 基于 return_rate_day1/2/3

# 周几提取
weekday = recommend_date.weekday()  # 0=周一, 6=周日

# 月份提取
month = recommend_date.month
```

### 图表库选择

使用 **Chart.js**（通过 react-chartjs-2），原因：
- 轻量级，适合当前需求
- 支持柱状图、折线图、直方图
- 社区活跃，文档完善
- 比 ECharts 更轻量，比 Recharts 更灵活

## 实现计划

### 第一阶段：后端 API（3天）

1. 创建 `analysis_service.py`
   - 实现 `get_weekday_stats()`
   - 实现 `get_holding_period_stats()`
   - 实现 `get_return_distribution()`
   - 实现 `generate_insights()`

2. 创建 `app/routers/analysis.py`
   - 注册4个 API 端点
   - 添加参数验证
   - 添加限流（10次/分钟）

3. 测试 API
   - 单元测试统计逻辑
   - 集成测试 API 响应

### 第二阶段：前端页面（4天）

1. 安装依赖
   - `npm install chart.js react-chartjs-2`

2. 创建组件
   - `AnalysisPage.tsx` - 主页面
   - `WeekdayChart.tsx` - 周几胜率图
   - `HoldingPeriodChart.tsx` - 持仓周期图
   - `ReturnDistribution.tsx` - 收益分布图
   - `InsightCard.tsx` - 洞察卡片

3. 集成 API
   - 在 `services/api.ts` 添加分析接口
   - 实现数据加载和错误处理

4. 路由配置
   - 在 `App.tsx` 添加 `/analysis` 路由
   - 在 `Navbar.tsx` 添加导航入口

### 第三阶段：优化与测试（2天）

1. 性能优化
   - 添加数据缓存（内存缓存，TTL 5分钟）
   - 优化大数据量查询

2. 用户体验
   - 添加加载状态
   - 添加空数据提示
   - 响应式布局适配

3. 测试
   - 手动测试各种数据场景
   - 验证洞察生成逻辑

## 风险与应对

| 风险 | 影响 | 应对措施 |
|-----|------|---------|
| 历史数据量不足 | 统计结果不准确 | 显示数据量提示，建议积累足够数据后再分析 |
| 查询性能问题 | 页面加载慢 | 添加缓存，优化 SQL 查询 |
| 洞察逻辑错误 | 给出错误建议 | 充分测试，添加数据验证 |
| 图表显示问题 | 用户体验差 | 使用成熟图表库，添加 loading 状态 |

## 成功指标

1. **功能完整性**：4个分析维度全部实现
2. **性能**：API 响应时间 < 2秒
3. **用户体验**：洞察清晰易懂，图表交互流畅
4. **数据准确性**：统计结果与手动计算一致
